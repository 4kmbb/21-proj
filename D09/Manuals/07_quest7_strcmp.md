## 2. Что делает `strcmp`

`s21_strcmp(str1, str2)` сравнивает две строки **посимвольно** и
возвращает:

| Результат | Значение |
|---|---|
| `0` | строки полностью совпадают |
| `< 0` | первая строка лексикографически меньше |
| `> 0` | первая строка лексикографически больше |

Важно: стандарт гарантирует только **знак** результата, а не конкретное
число. Поэтому в тестах мы проверяем именно знак: `-1`, `0` или `1`.

Примеры:

```text
"abc" и "abc"  -> 0
"abc" и "abd"  -> отрицательное число
"abd" и "abc"  -> положительное число
""    и "abc"  -> отрицательное число
"abc" и ""     -> положительное число
```

## 3. Как работает лексикографическое сравнение

Сравниваем символы с одинаковыми индексами:

```text
"abc"
"abd"
 ^
 'a' == 'a' -> идём дальше

"abc"
"abd"
  ^
 'b' == 'b' -> идём дальше

"abc"
"abd"
   ^
 'c' != 'd' -> сравниваем 'c' - 'd' < 0
```

Если одна строка закончилась раньше, а другая ещё нет, то более
короткая считается меньше. Например, `"abc"` меньше `"abcd"`.

## 5. Реализация `s21_strcmp`

> Номера строк в таблице ниже считаются внутри показанного фрагмента.

```c
/*
 * Сравниваем две строки посимвольно.
 * Возвращаем:
 *   0  — строки одинаковые;
 *   <0 — первая строка "меньше";
 *   >0 — первая строка "больше".
 */
int s21_strcmp(const char* str1, const char* str2) {
    int result = 0;
    int i = 0;

    // Идём, пока строки совпадают и хотя бы одна ещё не закончилась
    while (result == 0 && (str1[i] != '\0' || str2[i] != '\0')) {
        result = (unsigned char)str1[i] - (unsigned char)str2[i];
        i++;
    }

    return result;
}
```

### Разбор каждой строки

| Строка | Что написано | Что это значит |
|---|---|---|
| 1–6 | комментарий | Объясняет смысл возвращаемого значения. |
| 7 | `int s21_strcmp(const char* str1, const char* str2) {` | Начало функции. |
| 8 | `int result = 0;` | Пока строки считаются равными. |
| 9 | `int i = 0;` | Индекс текущего символа. |
| 10 | пустая строка | Разделитель. |
| 11 | комментарий | Поясняет условие цикла. |
| 12 | `while (result == 0 && (str1[i] != '\0' \|\| str2[i] != '\0')) {` | Продолжаем, пока не нашли различие и хотя бы одна строка не закончилась. |
| 13 | `result = (unsigned char)str1[i] - (unsigned char)str2[i];` | Считаем разницу кодов символов. Приведение к `unsigned char` делает сравнение корректным для любых байтов. |
| 14 | `i++;` | Переходим к следующему символу. |
| 15 | `}` | Конец цикла. |
| 16 | пустая строка | Разделитель. |
| 17 | `return result;` | Возвращаем `0`, отрицательное или положительное число. |
| 18 | `}` | Конец функции. |

### Почему `unsigned char`, а не просто `char`

Тип `char` может быть знаковым или беззнаковым — это зависит от
компилятора. Если `char` знаковый, то байт `0xFF` превратится в `-1`,
и разница может получиться неправильной. Приведение к `unsigned char`
даёт стабильное сравнение в диапазоне `0..255`.

### Почему нельзя вернуть просто `1` или `-1`

Можно, но стандартный `strcmp` возвращает разницу кодов. Нам важнее
знак. Наша реализация возвращает именно разницу, как это делает
большинство стандартных реализаций.

### Почему в условии `||`, а не `&&`

Нам нужно продолжать, пока **хотя бы одна** строка не закончилась.
Если использовать `&&`, цикл остановится, когда закончится любая из
строк, и мы не сможем сравнить, например, `"abc"` и `"abcd"` до конца.
При этом `result == 0` гарантирует, что на предыдущих символах различий
не было.

## 6. Тесты `s21_strcmp_test`

> Номера строк в таблице ниже считаются внутри показанного фрагмента.

### Код

```c
/*
 * Один тест для s21_strcmp.
 * expected_sign: -1 (первая меньше), 0 (равны), 1 (первая больше).
 */
static void s21_strcmp_case(const char* left, const char* right, int expected_sign) {
    int actual = s21_strcmp(left, right);

    // Приводим результат к -1/0/1, чтобы проверять только знак
    int actual_sign = (actual > 0) - (actual < 0);

    printf("Input: \"%s\" vs \"%s\" | Output: %d | Expected sign: %d | ", left, right, actual, expected_sign);
    print_result(actual_sign == expected_sign);
}

/*
 * Тесты для s21_strcmp:
 * одинаковые строки, разные строки в обе стороны,
 * пустая строка слева и справа.
 */
void s21_strcmp_test(void) {
    printf("=== Testing s21_strcmp ===\n");
    s21_strcmp_case("abc", "abc", 0);
    s21_strcmp_case("abc", "abd", -1);
    s21_strcmp_case("abd", "abc", 1);
    s21_strcmp_case("", "abc", -1);
    s21_strcmp_case("abc", "", 1);
    printf("\n");
}
```

### Разбор каждой строки

| Строка | Что написано | Что это значит |
|---|---|---|
| 1–4 | комментарий | Поясняет параметры теста. |
| 5 | `static void s21_strcmp_case(const char* left, const char* right, int expected_sign) {` | Один тест: две строки и ожидаемый знак результата. |
| 6 | `int actual = s21_strcmp(left, right);` | Вызываем нашу функцию. |
| 7 | пустая строка | Разделитель. |
| 8 | комментарий | Поясняет приведение к знаку. |
| 9 | `int actual_sign = (actual > 0) - (actual < 0);` | Если `actual > 0`, первое сравнение даёт `1`, второе `0`, результат `1`. Если `actual < 0` — `0 - 1 = -1`. Если `0` — `0 - 0 = 0`. |
| 10 | пустая строка | Разделитель. |
| 11 | `printf("Input: \"%s\" vs \"%s\" \| Output: %d \| Expected sign: %d \| ", left, right, actual, expected_sign);` | Печатаем обе строки, фактический результат и ожидаемый знак. |
| 12 | `print_result(actual_sign == expected_sign);` | Сравниваем знаки и печатаем `SUCCESS`/`FAIL`. |
| 13 | `}` | Конец одного теста. |
| 14 | пустая строка | Разделитель. |
| 15–18 | комментарий | Поясняет набор тестов. |
| 19 | `void s21_strcmp_test(void) {` | Главная тестовая функция. |
| 20 | `printf("=== Testing s21_strcmp ===\n");` | Заголовок группы. |
| 21 | `s21_strcmp_case("abc", "abc", 0);` | Одинаковые строки. |
| 22 | `s21_strcmp_case("abc", "abd", -1);` | Первая меньше: `'c' < 'd'`. |
| 23 | `s21_strcmp_case("abd", "abc", 1);` | Первая больше. |
| 24 | `s21_strcmp_case("", "abc", -1);` | Пустая строка меньше непустой. |
| 25 | `s21_strcmp_case("abc", "", 1);` | Непустая строка больше пустой. |
| 26 | `printf("\n");` | Пустая строка после тестов. |
| 27 | `}` | Конец функции. |

### Почему проверяем знак, а не точное число

Стандарт говорит только, что результат меньше, равен или больше нуля.
Разные реализации могут вернуть `-1`, `-2`, `-97` и т. п. Поэтому
проверять `actual == -1` было бы неправильно: наша функция может
вернуть, например, `-1`, а тест для `""` и `"abc"` вернёт `-97`.

У нас:

```text
s21_strcmp("", "abc") = 0 - 97 = -97
```

Но знак отрицательный, значит, тест должен пройти.

## 10. Типичные ошибки

### Сравнение через `==`

```c
if (str1 == str2)  // сравнивает адреса, а не содержимое строк
```

Так сравниваются указатели, а не символы. Нужен цикл или `strcmp`.

### Выход за границу строки

Если не проверять `'\0'`, цикл может уйти дальше конца массива. Наша
функция останавливается, когда обе строки закончились.

### Знаковый `char`

Без приведения к `unsigned char` сравнение русских букв или байтов
с кодом больше `127` может дать неожиданный результат.

### Проверка точного значения в тесте

Правильно проверять знак. Конкретное число — деталь реализации.
