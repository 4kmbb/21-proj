# Quest 1. Модуль `data_module`

## 1. Что нужно было сделать

Нужно было «починить» модуль `src/data_module` так, чтобы
`src/data_module/data_module_entry.c` собирался и работал.

При этом нельзя было менять разбивку на файлы: архитектор уже согласовал
структуру проекта. Нужно было переиспользовать готовые файлы из
`src/data_libs`.

Пример из задания:

| Вход | Выход |
|---|---|
| `5`<br>`1 2 3 4 5` | `0.00 0.25 0.50 0.75 1.00` |

Этот результат — нормализация массива по формуле:

```text
новое_значение = (старое_значение - минимум) / (максимум - минимум)
```

Для чисел `1 2 3 4 5`:

- минимум = `1`;
- максимум = `5`;
- размах = `5 - 1 = 4`;
- `1 -> (1 - 1) / 4 = 0.00`;
- `2 -> (2 - 1) / 4 = 0.25`;
- `3 -> (3 - 1) / 4 = 0.50`;
- `4 -> (4 - 1) / 4 = 0.75`;
- `5 -> (5 - 1) / 4 = 1.00`.

## 2. Какие файлы участвуют

```text
src/
├── data_libs/
│   ├── data_io.h
│   ├── data_io.c
│   ├── data_stat.h
│   └── data_stat.c
└── data_module/
    ├── data_process.h
    ├── data_process.c
    └── data_module_entry.c
```

Логика такая:

1. `data_module_entry.c` — точка входа, читает `n`.
2. `data_io.c` — читает и печатает массив.
3. `data_stat.c` — считает минимум, максимум, среднее и дисперсию.
4. `data_process.c` — нормализует массив.

### Зачем нужен заголовочный файл

Заголовок — это «оглавление» модуля. Другие файлы подключают его и видят,
какие функции существуют, какие у них аргументы и что они возвращают.
Сама реализация лежит в `.c` и компилируется отдельно.

Защита `#ifndef / #define / #endif` нужна, потому что один и тот же
заголовок может подключиться дважды (например, через другой заголовок).
Без защиты компилятор увидел бы два объявления и мог выдать ошибку.

## 5. Файл `src/data_libs/data_io.c`

```c
#include "data_io.h"

#include <stdio.h>

/*
 * Читаем n чисел из стандартного потока ввода (stdin).
 * Массив data уже должен быть выделен вызывающей стороной,
 * потому что эта функция не знает, откуда взялось n.
 */
void input(double* data, int n) {
    for (int i = 0; i < n; i++) {
        // %lf нужен именно для double, а не для float
        scanf("%lf", &data[i]);
    }
}

/*
 * Печатаем массив в одну строку.
 * Числа разделяем пробелом, но после последнего числа пробел не ставим,
 * чтобы в конце строки не было "лишнего" символа.
 */
void output(double* data, int n) {
    for (int i = 0; i < n; i++) {
        if (i > 0) {
            printf(" ");
        }
        // По условию задачи все double выводим с двумя знаками после запятой
        printf("%.2f", data[i]);
    }
}
```

### Почему `scanf("%lf")`, а не `scanf("%f")`

В `printf` для `double` исторически используется `%f`, а в `scanf` —
именно `%lf`. Если перепутать, число прочитается неправильно или
программа поведёт себя непредсказуемо.

### Почему нет пробела после последнего числа

Если печатать `printf("%.2f ", ...)` на каждой итерации, в конце строки
появится «хвостовой» пробел. Автотесты могут сравнивать строки строго,
поэтому мы печатаем пробел только перед элементами с индексом больше нуля.

## 7. Файл `src/data_libs/data_stat.c`

```c
#include "data_stat.h"

/*
 * Ищем максимальный элемент.
 * Если массив пустой (n <= 0), просто возвращаем 0,
 * чтобы не обращаться к несуществующему data[0].
 */
double max(double* data, int n) {
    double result = 0.0;
    if (n > 0) {
        result = data[0];
        for (int i = 1; i < n; i++) {
            if (data[i] > result) {
                result = data[i];
            }
        }
    }
    return result;
}

/*
 * Ищем минимальный элемент.
 * Логика такая же, как в max, только знак сравнения другой.
 */
double min(double* data, int n) {
    double result = 0.0;
    if (n > 0) {
        result = data[0];
        for (int i = 1; i < n; i++) {
            if (data[i] < result) {
                result = data[i];
            }
        }
    }
    return result;
}

/*
 * Среднее арифметическое: сумма всех элементов / количество.
 */
double mean(double* data, int n) {
    double result = 0.0;
    if (n > 0) {
        double sum = 0.0;
        for (int i = 0; i < n; i++) {
            sum += data[i];
        }
        result = sum / n;
    }
    return result;
}

/*
 * Дисперсия: среднее значение квадратов отклонений от среднего.
 * Сначала находим среднее, потом складываем (data[i] - mean)^2
 * и делим на количество элементов.
 */
double variance(double* data, int n) {
    double result = 0.0;
    if (n > 0) {
        double average = mean(data, n);
        for (int i = 0; i < n; i++) {
            double difference = data[i] - average;
            result += difference * difference;
        }
        result /= n;
    }
    return result;
}

/*
 * Сортировка пузырьком по возрастанию.
 * На каждом проходе "большие" числа уходят в конец массива.
 * Для учебной задачи этого достаточно, а код получается понятным.
 */
void sort(double* data, int n) {
    for (int i = 0; i < n - 1; i++) {
        for (int j = 0; j < n - i - 1; j++) {
            if (data[j] > data[j + 1]) {
                double temporary = data[j];
                data[j] = data[j + 1];
                data[j + 1] = temporary;
            }
        }
    }
}
```

### Почему нельзя сравнивать `double` через `==`

Числа с плавающей точкой хранятся приближённо. Например, `0.1 + 0.2`
может дать не ровно `0.3`, а `0.30000000000000004`. Поэтому вместо
`if (size == 0)` используют `if (fabs(size) < EPS)` или
`if (fabs(size) > EPS)`.

## 9. Файл `src/data_module/data_process.c`

```c
#include "data_process.h"

#include <math.h>
#include <stdlib.h>

#include "../data_libs/data_stat.h"

/*
 * Приводим все числа к диапазону [0, 1].
 * Формула: (x - min) / (max - min).
 * Возвращаем 1, если нормализация получилась, и 0, если нет.
 */
int normalization(double* data, int n) {
    int result = 1;

    if (data == NULL || n <= 0) {
        // Некорректные входные данные — нормализовать нечего
        result = 0;
    } else {
        double max_value = max(data, n);
        double min_value = min(data, n);
        double size = max_value - min_value;

        /*
         * Если max и min совпадают, то size == 0 и делить на него нельзя.
         * Поэтому нормализуем только когда разница заметна.
         */
        if (fabs(size) > EPS) {
            for (int i = 0; i < n; i++) {
                data[i] = (data[i] - min_value) / size;
            }
        } else {
            result = 0;
        }
    }

    return result;
}
```

### Что было сломано в исходнике

В исходном коде условие было таким:

```c
if (fabs(size) < EPS) {
    for (...) {
        data[i] = data[i] / size - min_value / size;
    }
} else {
    result = 0;
}
```

То есть нормализация выполнялась как раз тогда, когда `size` почти ноль,
а значит, происходило деление на ноль. Мы поменяли знак на `>`:
нормализуем при **большом** размахе, а при маленьком сообщаем об ошибке.

## 10. Файл `src/data_module/data_module_entry.c`

```c
#include <stdio.h>
#include <stdlib.h>

#include "../data_libs/data_io.h"
#include "data_process.h"

/*
 * Точка входа модуля data_module.
 * Сначала читаем количество чисел, потом выделяем под них память,
 * затем читаем сами числа и нормализуем их.
 */
int main(void) {
    int n = 0;
    int status = 0;

    // Проверяем, что количество ввели корректно
    if (scanf("%d", &n) != 1 || n <= 0) {
        status = 1;
    } else {
        // Выделяем память под n вещественных чисел
        double* data = malloc((size_t)n * sizeof(double));

        if (data == NULL) {
            // Память не выделилась — дальше работать нельзя
            status = 1;
        } else {
            input(data, n);

            if (normalization(data, n)) {
                output(data, n);
                printf("\n");
            } else {
                printf("ERROR\n");
            }

            // Память, выделенную через malloc, обязательно освобождаем
            free(data);
        }
    }

    // Единственный выход из функции: 0 — успех, 1 — ошибка
    return status;
}
```

### Почему память выделяется в `main`, а не в `input`

Функция `input` получает уже готовый указатель. Если бы она сама выделяла
память, ей пришлось бы возвращать новый указатель, а по заданию её
прототип — `void input(double* data, int n)`. Поэтому ответственность за
`malloc` и `free` лежит на вызывающей стороне.

### Почему `int main(void)`, а не `void main()`

Стандарт C ожидает, что `main` возвращает `int`. По коду возврата
операционная система и автотесты понимают, успешно ли завершилась
программа. `void main()` — нестандартно и может давать предупреждение.

## 12. Типичные ошибки

### Забыли `malloc`

```c
double* data;      // указатель есть, но памяти нет
input(data, n);    // запись в случайный адрес — ошибка
```

Правильно:

```c
double* data = malloc((size_t)n * sizeof(double));
```

### Забыли `free`

Если память выделена и не освобождена, программа завершится, и ОС её
вернёт, но при проверке памяти (valgrind/ASan) будет утечка. В больших
программах утечки накапливаются и приводят к падению.

### Неверный формат `scanf`

```c
scanf("%f", &data[i]);   // неправильно для double
scanf("%lf", &data[i]);  // правильно
```

### Деление на ноль при нормализации

Если все числа одинаковые, `max - min == 0`. Нужно проверить размах
через `fabs(size) > EPS`, иначе программа может получить `nan` или
аварийно завершиться.

### Нет `#include <stdio.h>`

`scanf` и `printf` объявлены в `stdio.h`. Без подключения компилятор
может выдать предупреждение или ошибку.
