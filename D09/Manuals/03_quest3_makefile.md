# Quest 3. `main_executable_module` и Makefile

## 1. Что нужно было сделать

Нужно было:

1. Доработать `src/main_executable_module/main_executable_module.c`,
   чтобы программа собиралась и работала.
2. Написать `Makefile` в этой же папке.
3. Предусмотреть цели `all`, `clean`, `rebuild`.
4. Собирать исполняемый файл в папку `build` в корне проекта
   с именем `Quest_3`.
5. Не загружать результат сборки в репозиторий.

## 2. Что делает программа

Программа показывает полный конвейер обработки данных:

```text
ввод
  |
  v
сырые данные
  |
  v
нормализация в [0; 1]
  |
  v
сортировка по возрастанию
  |
  v
решение YES / NO
```

Пример запуска:

```bash
printf '5\n1 2 3 4 5\n' | ./build/Quest_3
```

Вывод:

```text
LOAD DATA...
RAW DATA:
	1.00 2.00 3.00 4.00 5.00
NORMALIZED DATA:
	0.00 0.25 0.50 0.75 1.00
SORTED NORMALIZED DATA:
	0.00 0.25 0.50 0.75 1.00
FINAL DECISION:
	NO
```

Почему `NO`: после нормализации среднее равно `0.5`, а для `YES`
нужно `>= 0.618`.

```text
src/

│   └── data_stat.c/.h

│   └── decision.c/.h
```

`main_executable_module.c` — это «дирижёр». Он не реализует статистику
и не читает числа сам, а вызывает готовые функции из других модулей.

## 4. Файл `src/main_executable_module/main_executable_module.c`

```c
#include <stdio.h>
#include <stdlib.h>

#include "../data_libs/data_io.h"
#include "../data_libs/data_stat.h"
#include "../data_module/data_process.h"
#include "../yet_another_decision_module/decision.h"

/*
 * Главная программа третьего задания.
 * Она показывает все этапы обработки данных:
 * ввод -> нормализация -> сортировка -> решение.
 */
int main(void) {
    int n = 0;
    int status = 0;

    if (scanf("%d", &n) != 1 || n <= 0) {
        status = 1;
    } else {
        double* data = malloc((size_t)n * sizeof(double));

        if (data == NULL) {
            status = 1;
        } else {
            printf("LOAD DATA...\n");
            input(data, n);

            printf("RAW DATA:\n\t");
            output(data, n);

            printf("\nNORMALIZED DATA:\n\t");
            if (normalization(data, n)) {
                output(data, n);

                printf("\nSORTED NORMALIZED DATA:\n\t");
                sort(data, n);
                output(data, n);

                printf("\nFINAL DECISION:\n\t");
                if (make_decision(data, n)) {
                    printf("YES\n");
                } else {
                    printf("NO\n");
                }
            } else {
                // Если нормализовать нельзя, дальнейшие шаги не имеют смысла
                printf("ERROR\n");
            }

            free(data);
        }
    }

    return status;
}
```

### Почему проверяется результат `normalization`

Если все числа одинаковые, `max - min = 0`, и нормализовать массив
нельзя. В этом случае нет смысла сортировать и принимать решение:
печатаем `ERROR` и завершаем обработку.

### Почему `sort` меняет массив, но ничего не возвращает

Сортировка работает прямо с переданным массивом. Ей не нужно создавать
копию: она переставляет элементы местами. Поэтому тип возврата `void`.

## 5. Функция `sort` из `data_stat.c`

> Ниже показан фрагмент файла. Номера строк в таблице считаются внутри
> этого фрагмента, а не от начала `data_stat.c`.

```c
void sort(double* data, int n) {
    for (int i = 0; i < n - 1; i++) {
        for (int j = 0; j < n - i - 1; j++) {
            if (data[j] > data[j + 1]) {
                double temporary = data[j];
                data[j] = data[j + 1];
                data[j + 1] = temporary;
            }
        }
    }
}
```

### Разбор каждой строки

| Строка | Что написано | Что это значит |
|---|---|---|
| 1 | `void sort(double* data, int n) {` | Функция сортировки. Массив передаётся указателем, изменения видны снаружи. |
| 2 | `for (int i = 0; i < n - 1; i++) {` | Внешний цикл: количество проходов. |
| 3 | `for (int j = 0; j < n - i - 1; j++) {` | Внутренний цикл: сравниваем соседние элементы. Хвост массива уже отсортирован, поэтому `- i`. |
| 4 | `if (data[j] > data[j + 1]) {` | Если левый больше правого, порядок неправильный. |
| 5 | `double temporary = data[j];` | Сохраняем левый элемент. |
| 6 | `data[j] = data[j + 1];` | Ставим правый на место левого. |
| 7 | `data[j + 1] = temporary;` | Ставим сохранённый левый на место правого. |
| 8 | `}` | Конец `if`. |
| 9 | `}` | Конец внутреннего цикла. |
| 10 | `}` | Конец внешнего цикла. |
| 11 | `}` | Конец функции. |

### Как это выглядит на примере

Массив `3 1 2`:

```text
проход 1:
3 и 1 -> меняем -> 1 3 2
3 и 2 -> меняем -> 1 2 3
проход 2:
1 и 2 -> не меняем -> 1 2 3
```

## 6. Файл `src/main_executable_module/Makefile`

```makefile
# Компилятор, которым собираем программу
CC = gcc

# Флаги: показываем предупреждения и считаем их ошибками,
# а также используем стандарт C11
CFLAGS = -Wall -Wextra -Werror -std=c11

# Папка build находится в корне проекта D09.
# Makefile лежит в src/main_executable_module, поэтому поднимаемся на два уровня вверх.
BUILD_DIR = ../../build
TARGET = $(BUILD_DIR)/Quest_3

# Все исходники, из которых состоит программа
SRC = main_executable_module.c \
      ../data_libs/data_io.c \
      ../data_libs/data_stat.c \
      ../data_module/data_process.c \
      ../yet_another_decision_module/decision.c

# Заголовки, от которых зависит сборка
HEADERS = ../data_libs/data_io.h \
          ../data_libs/data_stat.h \
          ../data_module/data_process.h \
          ../yet_another_decision_module/decision.h

# Цель по умолчанию: собрать исполняемый файл
all: $(TARGET)

# Собираем все исходники сразу в один исполняемый файл.
# -lm подключает библиотеку математики (sqrt, fabs).
$(TARGET): $(SRC) $(HEADERS)
	mkdir -p $(BUILD_DIR)
	$(CC) $(CFLAGS) $(SRC) -o $(TARGET) -lm

# Удаляем только результат нашей сборки
clean:
	rm -f $(TARGET)

# Полная пересборка: сначала очистка, потом сборка
rebuild: clean all

# Эти цели не являются файлами, поэтому объявляем их phony
.PHONY: all clean rebuild
```

### Что вообще такое Makefile

`make` — утилита сборки. Она читает `Makefile` и выполняет команды для
целей. Цель — это имя слева от двоеточия:

```makefile
цель: зависимости
	команда
```

Важно: **команды должны начинаться с символа табуляции**, а не с
пробелов. Если заменить таб на пробелы, `make` выдаст ошибку
`missing separator`.

### Почему пути относительные

Задание требует указывать пути относительно директории, где лежит
`Makefile`, потому что запускать его будут **из этой директории**. Поэтому:

- `../../build` — из `src/main_executable_module` вверх до `D09`, потом в `build`;
- `../data_libs/...` — подняться в `src` и зайти в соседнюю папку.

Если запустить `make` из корня проекта с `-f`, относительные пути
сломаются. Правильный запуск:

```bash
cd src/main_executable_module
make
```

или:

```bash
make -C src/main_executable_module
```

`-C` заставляет `make` сначала перейти в указанную директорию.

### Почему `-Wall -Wextra -Werror`

- `-Wall` — включает основные предупреждения.
- `-Wextra` — добавляет дополнительные.
- `-Werror` — превращает предупреждения в ошибки, чтобы не пропустить
  потенциальную проблему.

Это не требование синтаксиса, но хорошая привычка и требование проекта.

### Почему `-lm` стоит в конце

Порядок важен: сначала объекты/исходники, потом библиотеки, которые они
используют. Поэтому `-lm` добавлен после списка файлов.

## 9. Типичные ошибки

### Пробелы вместо таба в Makefile

Неправильно:

```makefile
all:
    gcc ...
```

Правильно — в начале команды должен быть именно таб. Многие редакторы
показывают его как стрелку или точку.

### Запуск `make` из другой директории

Если запустить `make` из корня без `-C`, `make` не найдёт Makefile.
Если указать `-f src/main_executable_module/Makefile`, относительные
пути будут считаться от текущей директории и могут сломаться.

### Забыли `mkdir -p build`

Если папки `build` нет, `gcc -o ../../build/Quest_3` не сможет создать
файл. Поэтому команда `mkdir -p` стоит перед компиляцией.

### Забыли `-lm`

Компоновщик не найдёт `sqrt`/`fabs` и выдаст ошибку вида
`undefined reference to sqrt`.

### `clean` удаляет лишнее

В нашем `clean` указан только `Quest_3`. Это хорошо: команда не удалит
исполняемые файлы других заданий из общей папки `build`.
