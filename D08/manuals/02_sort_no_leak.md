# Quest 2. Версия сортировки без утечек памяти

Файл программы: `src/sort_no_leak.c`.

## 1. Что требуется в задании

Нужно создать `src/sort_no_leak.c`, в котором нет утечки памяти из
`src/sort.c`.

Если утечки в `src/sort.c` не было, задание разрешает просто скопировать
`src/sort.c` в `src/sort_no_leak.c`.

В нашем случае `src/sort.c` уже написан без утечек. Поэтому логика двух
файлов одинаковая. Отличаются только комментарии.

## 2. Что такое утечка памяти

Утечка памяти — это ситуация, когда программа выделила память через `malloc`,
но не освободила её через `free`.

Пример утечки:

```c
int* a = malloc(n * sizeof(int));
// ... работа с массивом ...
// забыли free(a);
```

После завершения программы операционная система всё равно заберёт память,
но во время работы программы память остаётся занятой. В больших программах
это может привести к нехватке памяти.

Правильно:

```c
int* a = malloc(n * sizeof(int));
// ... работа с массивом ...
free(a);
```

## 3. Полный код

```c
#include <stdio.h>
#include <stdlib.h>

int input(int** a, int* n);
void sort(int* a, int n);
void output(const int* a, int n);
void free_array(int** a);

int main(void) {
    int n = 0;
    int* a = NULL;
    int status = input(&a, &n);

    if (status == 1) {
        sort(a, n);
        output(a, n);
    } else {
        printf("n/a");
    }

    // Главное отличие версии без утечек: память освобождается
    // и при успешной работе, и при любой ошибке ввода.
    free_array(&a);
    return 0;
}

// Читает размер, выделяет память под массив и вводит его элементы.
int input(int** a, int* n) {
    int status = 1;

    if (scanf("%d", n) != 1 || *n <= 0) {
        status = 0;
    } else {
        *a = (int*)malloc((size_t)*n * sizeof(int));
        if (*a == NULL) {
            status = 0;
        } else {
            for (int i = 0; i < *n && status == 1; i++) {
                if (scanf("%d", &(*a)[i]) != 1) {
                    status = 0;
                }
            }
        }
    }

    // Если выделенная память больше не нужна из-за ошибки, освобождаем ее.
    if (status == 0) {
        free_array(a);
    }
    return status;
}

// Сортировка выбором.
void sort(int* a, int n) {
    for (int i = 0; i < n - 1; i++) {
        for (int j = i + 1; j < n; j++) {
            if (a[j] < a[i]) {
                int temp = a[i];
                a[i] = a[j];
                a[j] = temp;
            }
        }
    }
}

// Вывод массива через пробел, без перевода строки в конце.
void output(const int* a, int n) {
    for (int i = 0; i < n; i++) {
        if (i > 0) {
            printf(" ");
        }
        printf("%d", a[i]);
    }
}

// Освобождение памяти и обнуление указателя.
void free_array(int** a) {
    if (a != NULL && *a != NULL) {
        free(*a);
        *a = NULL;
    }
}
```

## 4. Где именно освобождается память

Память может освобождаться в двух местах.

### Случай 1. Всё прошло успешно

1. `main` вызывает `input`.
2. `input` выделяет память и читает массив.
3. `main` сортирует и печатает массив.
4. `main` вызывает `free_array(&a)`.
5. Память освобождена.

### Случай 2. Ошибка во время чтения элементов

1. `input` выделил память.
2. На каком-то элементе `scanf` не смог прочитать число.
3. `status` стал `0`.
4. В конце `input` вызывается `free_array(a)`.
5. Память освобождена.
6. `main` получает `status == 0`, печатает `n/a`.
7. `main` снова вызывает `free_array(&a)`.
8. Второй вызов безопасен, потому что после первого вызова `a` стал `NULL`.

Именно поэтому `free_array` принимает `int**` и записывает `*a = NULL`.

## 5. Почему двойной `free` не происходит

Представим, что после ошибки указатель остался бы прежним:

```c
free(*a);
// *a всё ещё хранит старый адрес
```

Тогда повторный вызов `free(*a)` был бы ошибкой: нельзя освобождать один и
тот же адрес дважды.

Но у нас после освобождения выполняется:

```c
*a = NULL;
```

Теперь `*a` равен `NULL`. Проверка `*a != NULL` не пропустит второй `free`.

## 6. Сравнение с `sort.c`

Логика полностью совпадает:

- одинаковый ввод;
- одинаковое выделение памяти;
- одинаковая сортировка;
- одинаковый вывод;
- одинаковое освобождение памяти.

Разница только в комментариях:

- в `sort.c` комментарии подробнее описывают каждый шаг;
- в `sort_no_leak.c` есть комментарий, который подчёркивает, что память
  освобождается и при успехе, и при ошибке.

Это соответствует условию: если утечки не было, можно скопировать файл.

## 7. Как проверить утечки

### AddressSanitizer

Собрать программу с санитайзерами:

```sh
gcc -std=c11 -g -fsanitize=address,undefined src/sort_no_leak.c -o sort_no_leak
printf '10\n4 3 9 0 1 2 100 2 7 -1' | ./sort_no_leak
```

Если утечек нет, AddressSanitizer не выведет сообщений об ошибках.

### Valgrind

Если установлен `valgrind`:

```sh
gcc -std=c11 -g src/sort_no_leak.c -o sort_no_leak
printf '10\n4 3 9 0 1 2 100 2 7 -1' | valgrind --leak-check=full ./sort_no_leak
```

В конце должно быть:

```text
All heap blocks were freed -- no leaks are possible
```

## 8. Проверка ошибок

### Ошибка: `n <= 0`

```sh
printf '0' | ./sort_no_leak
```

Вывод:

```text
n/a
```

Память не выделялась, `free_array` ничего не делает.

### Ошибка: не хватает элементов

```sh
printf '5\n1 2 3' | ./sort_no_leak
```

Вывод:

```text
n/a
```

Память была выделена, но при ошибке чтения освобождена.

### Ошибка: вместо числа буква

```sh
printf '3\n1 abc 3' | ./sort_no_leak
```

Вывод:

```text
n/a
```

## 9. Частые ошибки

1. **Не освобождать память при ошибке ввода.** Это самая частая утечка.
2. **Освобождать память два раза.** Опасная ошибка, может привести к падению.
3. **Не обнулять указатель после `free`.** Тогда сложно понять, что память
   уже освобождена.
4. **Освобождать память до вывода.** Тогда программа будет читать
   освобождённую память — это неопределённое поведение.
5. **Забыть `stdlib.h`.** Компилятор не увидит `malloc` и `free`.
